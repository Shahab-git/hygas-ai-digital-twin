Written 2026-10-30 on `origin/main` 0d1a432 (branch `provenance-apply`). Source: `docs/registry_status_audit.md` (766 registry rows counted Confirmed by default, 16 with a DOK-ING line) and the provenance worksheet (`docs/provenance_worksheet.md`). The owner filled the first rows; the checker read the worksheet with 0 errors and 0 conflicts. **The owner's rule: Confirmed means confirmed by DOK-ING with a citable source; Confirmed values are never overwritten.**

Nothing in the engine, the snapshot (120 keys), the runtime, the dynamics layer, the what-if tab, a default, a registry JSON value, a workflow or `requirements.txt` changed. The status is display and parameter-table information only: no model reads it.

## 1. The rule (one function, one default)

`python/registry_status.py` (`resolve_row`) decides the status of a datasheet row; `equipment_datasheet.resolve_datasheets()` writes it into every row the app shows; `parameter_table` uses the same function. In this order:

1. **An explicit status on the row** is kept (the 48 `ESTIMATE_FILLS` rows keep "Engineering Estimate (Not Vendor/DOK-ING Confirmed)"). An explicit `Confirmed` with no citation is **not** honoured.
2. **An entry in `data/registry_status_overlay.json`** (generated from the owner's worksheet):

   | origin | needs | status |
   |---|---|---|
   | `DOK-ING` | `source` | Confirmed |
   | `SIMILAR_PLANT` | `source` | Estimated (shown as "Estimated (literature-informed)") |
   | `ASSUMED` | `note` (reason) | Assumed |
   | `CALCULATED` | `source` (formula / script) | Calculated |

   An entry that breaks its own rule (DOK-ING without a source, a status that does not match its origin, an unknown or blank origin) is **ignored**, so a corrupted overlay can never produce a Confirmed row. A missing or malformed overlay file means every row is Unverified.
3. **Otherwise: "Unverified (registry)"**: no stated origin yet. `UNKNOWN` and blank rows land here. Never a guess.

`equipment_datasheet.slot_status()` has **no default** any more (`:512` is gone). A slot is Confirmed only if at least one row is Confirmed **and** cites its source (`status_source`); otherwise it is the layout's single "not confirmed" slot. The slot badge text shows the evidence label of its best row (Confirmed, Calculated, Estimated (literature-informed), Engineering Estimate, Assumed, Unverified (registry)). `summarize()` keeps its three-way split and adds `evidence_label_slots` and `evidence_label_rows`.

## 4. What the labels mean

- **Confirmed (DOK-ING-sourced):** a DOK-ING source is cited (document, date, page/line or e-mail). Nothing else is Confirmed.
- **Estimated (literature-informed):** taken from a similar plant or the literature, with a source. Never Confirmed.
- **Assumed:** a design assumption of this project, with a stated reason.
- **Calculated:** derived from other values, with the formula or script named.
- **Engineering Estimate (existing fills):** the pre-existing explicit estimate fills, unchanged.
- **Unverified (registry):** no stated origin yet. The value is on file; where it came from has not been stated.
- **Missing Data — Required:** the slot has no row.

Caption in the app: "Confirmed means a DOK-ING source is cited; unverified rows have no stated origin yet."

## 7. How to add more answers

1. Edit the worksheet (`outputs/provenance/provenance_worksheet_filled.xlsx`, or a fresh one from `python scripts/make_provenance_worksheet.py`): fill `origin`, `source`, `note` for more rows (priority 1 rows first).
2. `python scripts/export_provenance_csv.py` (writes `data/provenance/provenance_worksheet_filled.csv`; needs `openpyxl` locally, which is not in `requirements.txt`).
3. `python scripts/check_provenance_worksheet.py data/provenance/provenance_worksheet_filled.csv` (read-only: errors, conflicts, and the before / today / would-be counts).
4. If valid: `... --write` regenerates `data/registry_status_overlay.json` with a new header. Commit the CSV and the overlay; run the suite.
